# Q&A — 제너레이터 표현식

## `(x for x in ...)`는 뭐라고 부르나
**제너레이터 표현식(generator expression)**. 예약어가 아니라 괄호 문법일 뿐.

## `[ ]` vs `( )` 차이
- `[x for x in ...]` (리스트 컴프리헨션): 즉시 전체를 메모리에 만듦 → 몇 번이든 재순회 가능
- `(x for x in ...)` (제너레이터 표현식): 값을 미리 안 만들고 `next()` 호출 시점에 하나씩 계산 (지연 평가) → 다 쓰면 소진, 재순회 불가

**왜 생겼나**: 메모리 절약. 데이터가 아주 크거나 무한 시퀀스일 때 전체를 메모리에 올리지 않기 위해 (PEP 289).

## 정신 모델: 큐가 아니라 "일시정지된 계산"
미리 채워둔 큐(값 저장)가 아니라, 갖고 있는 건 딱 두 가지뿐:
1. 값을 어떻게 계산하는지 (레시피)
2. 지금 어디까지 왔는지 (상태)

`next()` 호출 시점에 그 자리에서 계산해서 던지고 멈춤. 그래서 `sum(gen)`이 다 소진시키면 `max(gen)`은 빈 상태만 받음.

## 제너레이터를 유지하면서 고치는 법
1. **한 번만 순회** (권장) — `sum`/`max`를 따로 부르지 말고 `for` 루프 하나로 합계와 최댓값을 같이 계산
2. **`itertools.tee`** — 원본을 독립된 두 이터레이터로 복제. 단, 진행 속도 차이만큼 내부 버퍼링이 생겨 메모리 절약 효과가 줄어듦. 정말 서로 다른 곳에 각각 넘겨야 할 때만 사용

## 성능: 내장 함수 두 번 vs 수동 루프 한 번
- **리스트(재순회 가능)**: `sum()`+`max()`는 C로 구현돼 있어서, 2번 순회해도 대개 수동 파이썬 루프(1번 순회, 원소마다 파이썬 바이트코드)보다 빠름. 순회 횟수보다 인터프리터 오버헤드가 더 큰 영향을 줌.
- **제너레이터(재순회 불가)**: 애초에 "두 번 부를지"를 선택할 수 없음(두 번째 호출이 에러). 성능과 무관하게 단일 루프가 유일한 정답.
