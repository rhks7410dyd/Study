# 연습 — 공유 리스트 버그 찾기

- 문제: `problem.py`의 `ShoppingCart`가 서로 다른 인스턴스인데도 아이템 목록을 공유한다.
- 유형: 디버깅 (클로저 예제보다 난이도 상향 — 스코프가 아니라 인자 기본값의 생명주기 문제)

## 재현
```python
cart_a = ShoppingCart("A")
cart_a.add_item("apple")

cart_b = ShoppingCart("B")
cart_b.add_item("banana")

print(cart_a.name, cart_a.items)
print(cart_b.name, cart_b.items)
# 기대: A ['apple'] / B ['banana']  (서로 독립된 목록)
# 실제: ?
```
직접 `python problem.py`로 실행해서 실제 출력을 확인해보세요.

## 진행 방법
[[../../Concepts/디버깅-루틴|디버깅 루틴]]을 따라 아래 순서로 풀어보세요. AI 도구 없이 먼저 시도할 것.

1. 재현 — 위 코드를 실행해서 실제로 두 카트가 아이템을 공유하는지 확인
2. 가설 — 왜 `cart_a`와 `cart_b`가 같은 리스트를 참조하게 되는지 문장으로 적기
3. 검증 — 가설대로 수정 후 재실행해서 두 목록이 독립적인지 확인

## 접근
현재 init func (뭐라고부르는지 모르겠네)을 보면 items=[]으로 default가 선언된 리스트로 받고 있다. 
init은 class를 초기화하는 함수이기 때문에 클래스가 처음호출 될 때 초기화로 한번 실행? 되는 느낌이고, __new__는 그게 아니라 매번 실행되는 느낌이라 차이가 있어서그 문제일 것으로 판단됨.
이 리스트는 상수처럼 객체 자체를 받는 것이기 때문에 cart_a, cart_b를 선언할 때 같은 리스트를참조하게 되고,
그렇기 때문에 __new__로 바꾸어주면 된다.

지금은 내가 생각한대로 선언시 새로운 list를 `list()`를 통해 생성해주는 식으로 해결했지만, 해당 방식이 아닌 init을 수정함에 따라 변경하는 방법도 있을 것으로 생각됨.

## 회고
접근의 윗문다는 그냥 `__new__`를 모르는 무지한 나의 잘못된 생각이고, 클로드에게 피드백을 요청하니 우선 이 문제에서는 아래와 같은 두 가지를 정리해 놔야될 필요성을 알게 되었다.
1. `__init__`과 `__new__`의 차이점 정리
2. 새로운 인스턴스를 default 매개변수처럼 사용해서 공유하지 않는 방법 (해답 자체)

1번의 경우, 개념적인 부분이기에 자세한 사항은 따로 정리한다.

### 2번 (해답 풀이)
클로드가 내준 방안은 default 파라미터를 리스트가 아닌 None으로 선언하는 것이다.
```
def __init__(self,name,items=None):
```

이러한 식으로 선언하였을 때, 실제 선언시 이미 존재하는 리스트인스턴스를 참조하게 되면 items가 그 리스트로 받게되지만, 선언시 리스트가 없다면 `items=None`이 되버린다.
그리고 실제 구현시 `self.items= items` 부분을 아래와 같이 바꾼다.
```
self.items= items if items is not None else []
```
이런 식으로 구현할 경우, 매개변수로 받은 `items`가 `None`인 경우 `__init__`이 호출 될 때마다 내부에서 새로운 리스트 인스턴스를 생성하여 연결하기에 공유 리스트가 생성되지 않는다.
